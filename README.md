# adaptive-language-coach

Универсальный Agent Skill для персонализированных языковых занятий на 15 или 30 минут. Один общий `SKILL.md`, вымышленный публичный пример конфигурации и отдельный приватный профиль. Не требует API для проведения уроков: нужен агент, способный читать инструкции и вести диалог.

## Быстрый старт

1. Откройте эту папку в агенте с доступом к файлам и попросите прочитать `SKILL.md`. Для автоматического обнаружения установите **всю папку** в каталог skills вашего хоста по его инструкции; просто клонирование репозитория не гарантирует обнаружение. Не устанавливайте два экземпляра одновременно.
2. Начните диалог. Агент сам спросит язык, цели, интересующие темы, жизненный/рабочий контекст и примерный уровень, затем создаст приватный профиль и персональный план уроков. Заполнять JSON, загружать протоколы занятий или вести таблицы не требуется. Существующие данные сохраняются. [Контракт конфигурации](references/configuration.md) предназначен для агента и разработчиков.
3. Скажите: **«Давай начнём урок»**, «Позанимаемся языком 30 минут» или “Let's start a language lesson”. При проблемах с обнаружением явно попросите использовать `adaptive-language-coach` из этой папки.
4. Агент прочитает профиль и историю, проведёт урок и будет сам пополнять словарь, журнал ошибок и прогресс по ходу ответов. После каждого блока сохранит контрольную точку, а в конце обновит план следующего занятия. Полностью автоматическое сохранение требует доступа на запись; без него агент ведёт черновик в чате и выдаёт единый экспорт `UNSAVED`.

Для повседневной работы в ChatGPT: [настройка Project и готовые инструкции](docs/chatgpt-project.md). Для Claude: [настройка и проверка](docs/claude-setup.md). Не требуется копировать личные сведения в общий skill.

## Что делает урок

Recall → grammar → vocabulary → speaking с коррекцией и повторной попыткой → самостоятельные предложения → writing → mini-test → полный Markdown-конспект. [Точный протокол](references/lesson-protocol.md) распределяет время и ограничивает speaking, чтобы остальные блоки не исчезали. В конце агент показывает весь конспект с заданиями, реальными ответами, исправлениями, оценкой и коротким тестом, а также сохраняет [контекст следующего занятия](references/lesson-handoff.md). При запросе саммари он показывает доступный конспект целиком; отсутствующие ответы или блоки не восстанавливает по догадке.

На занятие вводятся 3–5 целевых выражений: контекст, самостоятельное употребление и повторение D+1/3/7/14. На старте пользователь задаёт цели, интересующие темы и ситуации из своей жизни и работы; рабочий контекст можно пропустить, если он неактуален. Агент уточняет предполагаемый уровень, а затем по реальным ответам формирует отдельные предварительные оценки письма, речи и грамматики. Темы занятий связываются с выбранными контекстами и целями. [Оценка](references/assessment.md) использует отдельные навыки, исходные ответы, размер выборки и уровень помощи. Похвала не выдаётся автоматически; оценка уровня остаётся гипотезой, пока нет достаточных данных.

Для начинающего с нуля есть [маршрут A0/pre-A1](references/absolute-beginner.md): узнавание → повторение → замена элемента → собственная короткая фраза → предложение. Ученик может отвечать одним словом, выбирать вариант и лишь постепенно переходить к речи и письму. Все блоки остаются в уроке, но ограниченная попытка честно помечается как упрощённая; узнавание или копирование не выдаются за самостоятельное владение.

По желанию можно задать частоту и удобные дни/время занятий: агент учтёт это в личном плане и предложит следующее окно практики. Предпочтение не запускает урок или напоминание автоматически; пропуск дня не считается ошибкой в повторении.

## Структура

```text
adaptive-language-coach/
├── SKILL.md                    # единственный общий skill
├── config/example.json         # вымышленный публичный профиль
├── config/schema.json          # JSON Schema + проверки в scripts/validate.py
├── references/                 # протокол, оценка, записи, ограничения, Notion
├── docs/chatgpt-project.md      # настройка и инструкции для Project
├── examples/lesson.md          # вымышленное проведённое занятие
├── templates/                  # шаблоны конспекта и состояния
├── scripts/                    # валидация и чистые функции календарного SRS
├── tests/                      # автоматические контракты + ручные сценарии
├── .github/workflows/          # CI для будущего GitHub-репозитория
└── private/                    # личные данные; НЕ входят в Git
```

В публичном примере — немецкий → испанский, A2 → B1, бытовые темы. Это демонстрационные значения, не сведения о владельце репозитория. Секция Notion отсутствует в example; её разрешённая форма описана в схеме только для приватной конфигурации. [Процедура синхронизации](references/notion-sync.md) выполняется лишь по отдельной команде и при доступном коннекторе.

## Локальная проверка

Python 3.9+ с IANA timezone database (на некоторых платформах установите `tzdata`). Зависимости нужны только для разработки и проверки, не для диалогового использования skill.

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python scripts/validate.py
.venv/bin/python scripts/validate.py --private private/config.json
.venv/bin/python -m unittest discover -s tests -v
```

На Windows используйте `.venv\Scripts\python.exe`. [Сценарии поведения](tests/scenarios.md) предназначены для ручного прогона в целевом агенте: unit tests не доказывают, что модель соблюдает протокол или укладывается во время. [Отчёт локальной проверки](docs/validation.md) отделяет выполненные проверки от ещё не проведённых занятий.

## Приватность и подготовка к публикации

`private/`, окружение и файлы `*.private.*` исключены через `.gitignore`. Не переносите личные примеры, адреса Notion, записи уроков или секреты в публичные файлы. Перед любой будущей публикацией проверьте:

```bash
git status --short --ignored
git check-ignore private/config.json
git ls-files
git diff --cached --check
git diff --cached
```

Ignore не очищает уже отслеживаемые файлы или историю и не защищает от `git add -f`. Публичные архивы создавайте только из проверенного публичного manifest, а не архивированием всей рабочей папки. История и облачные копии требуют отдельной проверки, если туда ранее попали данные. Репозиторий не содержит функции публикации на GitHub.

## Ограничения

Это инструкции для агента, а не приложение с таймером и фоновыми задачами. Запуск зависит от сообщения пользователя и обнаружения skill хостом. Голосовые возможности и доступ к исходному аудио зависят от среды; по одному тексту нельзя оценить произношение. Время без часов оценивается приблизительно. Файлы, память между чатами и Notion требуют реальных доступных инструментов. Подробности: [ограничения](references/limitations.md).
